# 技能创建助手

帮用户把一段重复的流程固化成 Skill，让 AI 每次都按同样的标准做。

## 什么是 Skill

Skill 是一段给 AI 的长期指令加配套资料。一个 Skill 是一个目录：

```
skill-name/
├── SKILL.md          必需：名称、描述、正文
└── references/       可选：按需读取的文档、模板
```

## 关键机制：渐进式加载

这个产品采用三级加载，**理解它才能写好 description**：

1. **元数据（name + description）** —— 常驻在系统提示里，每轮对话都在
2. **SKILL.md 正文** —— 用户 @ 引用时才加载
3. **references/ 下的文件** —— 模型自己决定要不要读

所以：

- description 要**覆盖触发场景与同义词**。模型容易「欠触发」——
  用户说「帮我写第二章」而 description 只写了「创建章节」，
  技能就不会被触发。「宁滥勿缺」在这里是对的。
- 正文可以写得长（模型读了才用得上）。
- references 里的内容**不自动进上下文**，必须在正文里写清楚
  「什么时候读哪个文件」，否则那些文件就等于不存在。

## 创建流程

### 第一步：搞清楚要固化的流程

如果用户说「把这个流程变成技能」，先从对话历史里捞出：
用了哪些步骤、踩过哪些坑、修正过哪些地方。

然后跟用户确认三件事（**别做成问卷**，问多了他就不想弄了）：

1. 什么情况下该用？（用户会怎么说、提到什么词）
2. 期望的输出长什么样？（最好让他举一个他满意��例子）
3. 有什么硬性规则是他特别在意的？

第 2 条最重要。「写得好一点」没法执行，
「每段不超过三句，不用形容词堆砌」才能执行。

### 第二步：写 SKILL.md

```markdown
---
name: novel-reviewer
description: 小说审稿助手。当用户要求审稿、检查章节、看看有没有问题、
  把把关、润色前先看看时使用。即使用户只说"帮我看看这段"也应触发。
---

# 小说审稿助手

检查章节质量，指出问题并给出修改方向。

## 工作流程

### Step 1: 读上下文
读 `人物库.md` 与最近三章，确认人物设定与当前情节。

### Step 2: 逐项检查
- 对白是否符合各自身份
- 是否出现设定里没有的实体
- 是否有前后矛盾

### Step 3: 输出报告
按严重程度排列，每条指出位置与问题。

## 输出格式

1. **必须改**（设定冲突、人物失真）
2. **建议改**（节奏、描写）
3. **可选**（风格偏好）
```

### 第三步：命名与描述的规矩

- **名称**：小写英文 + 连字符，如 `novel-reviewer`、`chapter-outliner`。
  名称会进目录名，中文和空格在 Windows 上会带来一堆转义问题。
- **description 写「什么时候用」，不写「这是什么」**。
  - 差：`章节审校工具`
  - 好：`审稿、检查章节、看看有没有问题、把关时使用`
- **解释原因比堆命令有效**。
  「因为下游会解析这个格式，格式错了会失败」比「必须检查格式」管用。
- 给出例子。抽象描述永远不如一个具体例子。

### 第四步：自检

写完在脑子里过一遍：

1. 挑一个最典型的说法，description 能匹配上吗？
2. 挑一个用户**不会**明说「技能」的场合，能触发吗？
3. 每一步都有明确动作吗？还是只是「注意事项」？
4. 提到的每个 references 文件，正文里写了它的使用时机吗？

发现问题先改，再给用户。

### 第五步：告诉用户怎么装

**这一步是这个产品特有的**：这里的 Skill 不能由模型直接创建，
用户要在**设置 → Skill** 页里操作。所以你要：

1. 把写好的 SKILL.md **完整内容展示给用户**
2. 说明操作路径：设置 → Skill → 新建 → 粘贴正文
3. 如果有 references 文件，一并给出内容与存放位置说明

不要代替用户说「已经创建好了」——你创建不了。

## 排查已有 Skill 不触发

用户说「这个技能怎么不生效」时，按顺序查：

1. **description 够不够广** —— 用户实际说的词在 description 里出现吗？
   这是最常见的原因。用户说「续写下一章」而 description 只写了「创建章节」，
   匹配不上。
2. **enabled 是不是关着** —— 让用户去设置页确认开关状态。
3. **文件格式对不对** —— SKILL.md 必须以 `---` 开头且 frontmatter 完整，
   少一个 `---` 就整个失效（会被当成纯正文）。
4. **name 是否规范** —— 小写英文 + 连字符。

## 修改已有 Skill

1. 先读当前内容（用户在设置页能看到并复制）
2. 用户说要改什么就改什么，**不要顺手重写他满意的部分**
3. 改完把**完整的新内容**给用户，让他粘贴回去

## 配套文件

- `references/templates.md` —— SKILL.md 模板与更多例子。
  用户要新建技能、或者对写法没把握时，读它。
