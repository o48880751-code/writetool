# 一致性检查与文档同步

长篇写到几十上百章，矛盾不是"写错了"，是**维护文档和正文脱节**：
角色第 9 章重伤、第 12 章又"左手持剑"，往往是因为人物库从没更新过状态。

本技能的职责就是把两边对齐，并把每一次不对齐**指名道姓地**报告出来。

## 数据在哪

```
设定/人物库.md    ← 角色设定 + 状态变更记录
设定/世界观.md    ← 地理、势力、力量体系、历史
章节摘要.md       ← 每章摘要 + 关键设定句 + 埋下的伏笔
```

⚠ 章节正文在软件数据库里，不在文件树里。用户已写好的章节可在对话里 @ 引用。

## 模式 A：一致性检查（"有没有前后矛盾"）

### Step 1：全量读取

读三份维护文档 + 检查范围内的章节。
用户没指定范围时，默认**最近 10 章 + 三份维护文档**；
超过 30 章的项目提醒用户分批检查，别一次性全读。

### Step 2：四类冲突逐项核对

按以下四类扫描，每条命中必须落到"章-句-冲突对象"三级：

1. **实体冲突**：正文出现人物库/世界观之外的名字，
   或同名实体属性前后不一（名字写法、身份、境界）
2. **状态冲突**：角色状态与时间线不符——伤势、境界、位置、生死、持有物
   在 A 章确立后，B 章无故回退（"上一卷已死的角色这卷在说话"）
3. **设定规则冲突**：力量体系或世界规则被违反
   （凡人在前章无铺垫地用了灵力、功法效果与前文描述矛盾）
4. **库滞后冲突**：正文已确立的新设定（新角色、新地点、新伏笔）
   没有写回维护文档——这类不报错，单列"待入库"清单

### Step 3：输出冲突报告（只报告，不改写）

格式：

```
发现 3 处前后不一致：

1. [状态冲突] 第 7 章「夜枫右手持剑」，但第 12 章写的是「左手」——
   右臂在第 9 章受过重伤，人物库.md 中状态仍为「右臂重伤未愈」。
2. [实体冲突] 第 8 章新出现角色「墨染」，人物库.md 中无此条目；
   该角色已使用灵力，但世界观.md 力量体系未提及她如何获得修行能力。
3. [库滞后] 第 11 章埋下伏笔「袖口血纹」，章节摘要.md 里没有记录这条伏笔。
```

**红线**：用户没让你改正文，就一个字都不改。
冲突常有两种合法解法（正文错了 / 库旧了），判哪边对是作者的权力，不是你的。
逐条给出"建议处置"（改正文 / 更新库 / 需要新设定说明），由用户裁决。

### Step 4：按裁决执行修复

用户对每条冲突给出裁决后：

- 判「库旧了」→ 更新维护文档（走下面的模式 B 的确认流程）
- 判「正文错了」→ 该章交给「章节修订」技能走修订流程
  （读回原文 → 保护句 → 备份 → 覆盖），**不在本技能内直接改正文**
- 判「需要新设定」→ 请用户口述设定，再入库

## 模式 B：文档同步（"同步文档/更新维护文档"）

写完几章没顾上维护时，增量对齐：

### Step 1：找出未入库章节

对比 `章节摘要.md` 已收录的章号与已有章节，列出中间漏掉的章节。

### Step 2：逐章生成同步包

对每个未入库章节，从正文提取：

1. 一行摘要（核心情节，几句话）
2. 本章关键设定句（新实体、新伏笔、状态变更锚点——这些将作为日后修订的保护句依据）
3. 人物状态变更记录（谁、从什么状态、变成什么状态）
4. 本章新埋的伏笔（将来要回收的）

### Step 3：展示 + 确认后写入

把同步包完整展示给用户，问清楚要不要写入。
用户确认后一次性更新 `章节摘要.md`、`设定/人物库.md`、`设定/世界观.md`。

**格式优先**：三个文件一律**沿用用户当前格式**增补条目，
不重排、不恢复模板样式。用户手动调过结构的话，以他的文件为准。

## 单点检查（"对一下设定，看有没有写岔"）

用户只给了一段正文、没说要全查时，只做模式 A 的 Step 2 扫描，
范围限定在用户给的那段正文 + 三份维护文档。不必读全部章节。

## 模式 C：附表维护（"更新年表 / 伏笔回收表 / 势力矛盾表"）

`卷纲/` 下有四张结构表（格式见「长篇结构工程」技能）：
时间年表、势力矛盾表、伏笔回收对照表、专有名词索引。
表建了不更新就是废纸 —— 这一节管的是**让表跟着正文走**。

每写完一卷、或用户说"整理一下附表"时：

1. **伏笔回收表**：这一卷埋的新伏笔补进去（埋于第几章 / 内容 / 计划回收）；
   实际回收了的，状态从「未收」改成「已收」并填回收章节。
2. **时间年表**：补这一卷发生的、**会被后文引用**的时间点。不记流水账。
3. **势力矛盾表**：更新「当前状态」（潜伏 / 激化 / 已爆）；
   新势力先进清单，写清钱从哪来、粮从哪来、内部裂痕是什么。
4. **名词索引**：这一卷新出现的专有名词补进去。

⚠ **只补不删**。已有条目哪怕这一卷没动也别清掉 —— 它可能就是后面的伏笔。
⚠ 「弃收」是合法状态，但必须写理由。允许放弃，不允许忘记。

## 红线汇总

- **检查只报告，正文修改必须经用户裁决并移交「章节修订」**
- 每条冲突定位到章、句、冲突对象，不给"感觉有些不一致"这种空话
- 拿不准是正文错还是库旧时，列成问题问用户，不自行选择一边
- 发现无法归属的实体，标「待入库」而不是替用户编造它的设定
- **写入维护文档前必须问过用户**，不确认不写

## 配套文件

- `references/templates.md` —— 三份维护文档的字段模板。
  生成同步包、判断「待入库」条目该写入哪个字段时读它。
